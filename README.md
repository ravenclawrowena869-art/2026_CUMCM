# 2026 CUMCM 提交仓库

本仓库按“参赛论文 + 支撑材料”两部分组织，目标是在比赛结束时能够从当前正式结果直接构建最终提交镜像，而不是把赛中开发目录原样打包提交。

- `论文/`：存放论文工作稿、正式图表及最终参赛论文。
- `支撑材料/`：存放实际使用的源程序、自主查阅并实际使用的数据资料、论文依赖的必要中间结果、复现说明、AI 工具使用详情以及赛题要求的结果文件。

## 一、赛中与提交约定

1. 所有路径、文件名、代码注释、图片、文档内容与文档属性中不得出现参赛者姓名、队伍编号、学校、赛区等身份信息。
2. 赛题提供的原始附件不重复放入支撑材料；若使用自行查阅且实际进入模型或分析的外部数据，则放入 `支撑材料/02_自主数据/` 并注明来源。
3. 论文中的正式数值必须能够追溯到 `支撑材料/01_源程序/`、正式结果文件和必要中间结果，禁止论文与代码、数据、图表脱节。
4. 所有实际用于生成论文结果的源程序必须进入 `支撑材料/01_源程序/`，并保证可运行、可复现且与论文中的公式、参数和结果一致；论文附录中的代码应与最终提交版源程序保持一致。
5. C 题要求的 `result1.xlsx`、`result2.xlsx`、`result3.xlsx`、`result4-2.xlsx`、`result4-3.xlsx` 在最终提交镜像中保持官方文件名，并逐一进行可打开性、模板结构、单位和数值一致性检查。
6. 赛中持续维护 AI 使用记录；最终提交前由全队人工核验后，统一整理为官方要求的 `AI工具使用详情.pdf`。赛中 Markdown、原始聊天记录和内部任务包只作为整理证据，不默认进入最终提交包。
7. 支撑材料最终文件清单必须同步写入论文附录，并与最终压缩包中的实际文件逐项一致。
8. 最终论文、结果文件、源程序、复现说明、AI 使用详情和正式图表在封存前必须经过一致性检查；MD5 生成后不得再修改对应提交文件。

## 三、AI 工具使用说明

本队在竞赛过程中实际使用 WPS AI、ChatGPT、Codex / AI Coding Agent 等人工智能工具，主要用于赛题理解辅助、数据探索、文献检索辅助、候选模型讨论与比较、程序实现与调试、实验设计与批量计算、代码与数学一致性审查、结果复核、图表制作以及文字整理。

AI 输出不直接作为最终模型、正式数字或论文结论使用。涉及模型结构、参数、程序、图表和正式结果的内容，由队员结合题意与数据进行判断，并通过实际求解、独立复算、约束检查、模型检验、交叉审查或人工逐项复核后决定是否采纳。若 AI 建议与题意、数学约束、实际代码或实验结果冲突，以人工核验后的正式模型和结果为准。

当前详细互动证据分为三层：

- `支撑材料/AI互动原始记录.md`：保留关键 Prompt、AI 回复和人工后续；
- `支撑材料/AI互动补充/`：记录长任务回传、阶段知识库与当日重大模型修正过程；
- `支撑材料/AI工具使用详情.md`：面向最终 PDF 的阶段摘要和人工核验索引。

### 论文中的 AI 工具使用声明

论文参考文献之前建议采用与真实使用情况一致的表述：

> 本参赛队在竞赛过程中使用了AI工具，主要用于赛题理解、数据探索、文献检索辅助、模型方案比较、代码实现与调试、实验设计与结果核验、图表生成和文字整理，详细使用情况见支撑材料。

### `AI工具使用详情.pdf` 应覆盖

1. 实际使用的 AI 工具名称、版本或模型；
2. 具体使用目的和环节；
3. 主要提示方式和使用过程，可保留有代表性的交互摘要；
4. AI 输出中实际采纳、修改或否决了什么；
5. 队员如何完成数学、代码、数据、结果和论文层面的人工核验；
6. 对进入正式论文、代码、图表或核心结论的 AI 产物，记录相应的正式 artifact 和人工决定。

最终 AI 详情必须与真实使用深度一致。不能为了简化说明而弱化已经发生的模型讨论、代码生成、审查和实验设计，也不能把尚未执行的实验或未经核验的 AI 输出写成已完成工作。

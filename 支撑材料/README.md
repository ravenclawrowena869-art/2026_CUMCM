# 支撑材料目录（赛中工作区）

本目录在竞赛期间持续积累材料；**不要把 GitHub 下载得到的 ZIP 直接作为最终支撑材料提交**。最终冻结后，应先清理赛中占位文件和工作稿，再使用通用 WinRAR 将本目录压缩为 **RAR** 文件，且总大小不超过 20MB。

## 1. AI 工具使用详情

竞赛期间使用：

- `AI工具使用详情.md`：赛中持续更新真实 AI 使用过程，便于边做边记。

最终提交前：

1. 全队人工核验 Markdown 中的每条记录；
2. 整理并转换为 PDF；
3. PDF 必须命名为 **`AI 工具使用详情.pdf`**；
4. 检查 PDF 可正常打开、内容完整且无身份信息；
5. 删除赛中 `AI工具使用详情.md`，最终 RAR 中只保留 PDF。

## 2. C 题指定结果文件

以下 5 个文件完成后直接放在本目录根部，并保持官方文件名：

- `result1.xlsx`
- `result2.xlsx`
- `result3.xlsx`
- `result4-2.xlsx`
- `result4-3.xlsx`

## 3. 目录职责

- `01_源程序/`：论文模型与结果对应的**全部实际使用、完整、可运行源程序**。这些程序还必须完整进入论文附录，并与论文报告结果一致。
- `02_自主数据/`：仅放自行查阅并实际使用的数据或相关资料；赛题提供的原始附件不重复放入。若最终未使用外部数据或资料，可删除该目录。
- `03_中间结果/`：保存用于支撑模型、结果和结论，但不适合全部放入正文的较大图表、表格和必要数值结果。只保留正式证据，不保留无关调试垃圾。
- `04_复现说明/`：记录运行环境、入口程序、运行顺序、输入输出对应关系，以及论文图表和指标的生成路径。

## 4. Final Freeze 清理规则

最终制作 RAR 前必须完成：

- 删除仅用于占位、且没有提交价值的 README 或临时说明；
- 删除废弃模型、调试日志、重复图片、缓存、临时文件和旧版本结果；
- 保留真正承担“复现说明”功能的说明文件；
- 检查所有程序均可运行，且主要结果与论文一致；
- 将最终支撑材料的实际文件清单逐项写入论文附录；
- 检查文件内容、文件名、文件夹名和文档属性中均无姓名、队伍编号、学校、赛区等身份信息；
- 检查最终 RAR 小于 20MB。

最终提交操作和 MD5 冻结步骤见仓库根目录 `FINAL_SUBMISSION_CHECKLIST.md`。
